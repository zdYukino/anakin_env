# 下一步执行配置需求

A/B1 目前禁用。需要工程侧为固定的 G1 模型、传动、增益、控制模式及有效工况提供以下定义和验证依据；当前不会采用猜测值。

| 配置 | 需要提供的内容 |
| --- | --- |
| 逐关节速度预算 | canonical29 名称对应的实测 dq 上限，单位 rad/s；适用姿态、负载、策略/模式、触发后的处置，以及来源版本和验证记录。不能把期望命令的斜坡速度当作实测速度上限。 |
| 近限位/制动包络 | 逐关节裕量或可验证的状态相关停止包络；说明如何覆盖反馈年龄、发送/执行延迟、速度、加速度与力矩不确定性。当前允许的 40 ms 反馈年龄与名义 2 ms 周期必须纳入分析，q+.002*dq 不是完整包络。 |
| 饱和规则 | 明确判定对象和阈值（虚拟预期、编码预期、桥后实际力矩）、最大连续时长及跨模式/模型/epoch 的累计和复位规则，并给出验证依据。单测的示例时长不能作为执行配置。 |

Unitree G1 common/terminations.hpp 的统一 10 rad/s 默认值仅是待验证候选，尚不是本项目已验证的逐关节预算；未复制进配置。SDK 手臂示例的 0.5 rad/s 是示例命令斜坡，MJCF margin=0/solref 也不是停止包络。单元测试的 4 ms 是测试输入，不是允许饱和时长的依据。

预算补齐后仍需先将 alignment、hold、preparing/fallback、policy target 和 stop/damping 全部发送模式纳入统一验收，覆盖旧状态、延迟、模式切换和故障。采样时刻的预计总力矩不能证明桥后持续实际力矩边界。完成这些工作并冻结新执行版本后，才安排新的隔离仿真故障注入及浮动/切换验证；本检查点不开放任何 PD_REFERENCE 执行。
